# M1.4.4 Source Audit

## Exact dependency versions

- `attermann/microReticulum @ 0.5.0`
- `attermann/microStore @ 0.1.7`

## microStore 0.1.7 findings

`include/microStore/Adapters/NoopFileSystem.h`:

- adapter body is enabled only when `USTORE_USE_NOOPFS` is defined;
- type is `microStore::Adapters::NoopFileSystem`;
- it publicly derives from `microStore::FileSystem`;
- its constructor creates a `FileSystemImpl` backing object;
- `FileSystemImpl::init()` intentionally returns `false`;
- `storageSize()` and `storageAvailable()` both return zero.

`include/microStore/FileSystem.h`:

- `FileSystem::operator bool()` is based on `isValid()`;
- the base `FileSystemImpl::isValid()` returns true;
- therefore the no-op filesystem object is valid even though its `init()` operation returns false.

## microReticulum 0.5.0 finding

`Reticulum::start()` calls `OS::storage_size()` and `OS::storage_available()` before starting transport. A filesystem must therefore be registered even when Reticulum persistence/provisioning features are disabled in this application build.

## Local project changes

- `platformio.ini`: add `USTORE_USE_NOOPFS=1`.
- `src/reticulum/RnsNoopFileSystem.h`: bind to the exact adapter class and add compile-time guards.
- `src/reticulum/ReticulumService.cpp`: remove the incorrect `init()==true` requirement; validate/register the adapter before `Reticulum::start()`.
- `scripts/release_preflight.py`: enforce the feature macro, exact adapter type, absence of the bad root-level factory guess, absence of the false `init()` success gate, and registration order.

## Frozen behavior

No intentional changes to radio framing, RadioLib configuration, storage record formats, partitions, LXMF independent-send routing, or UI interaction behavior.
