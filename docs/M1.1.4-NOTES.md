# M1.1.5 — exact pinned-fork interface correction

M1.1.5 follows M1.1.3 without modifying the earlier archive.

## Why M1.1.3 failed

The user's PlatformIO compiler reached the exact RatSpeak microReticulum commit and
reported two concrete integration errors before link/upload:

1. `InterfaceImpl::send_outgoing(const Bytes&)` returns `void` at the pinned commit,
   while M1.1.3 incorrectly declared the T-Watch override as `bool`.
2. The M0.5-era `generate_microstore_compat.py` hook expected microStore headers, but
   the RatSpeak 0.2.10 fork resolved in this build does not supply a microStore
   dependency/header tree. RNS filesystem persistence is disabled in this endpoint
   anyway; application identity/inbox persistence remains on the dedicated FFat
   partition.

## M1.1.5 changes

- `WatchLoRaInterface::send_outgoing()` now exactly matches the compiler-observed
  pinned API: `void send_outgoing(const RNS::Bytes&)`.
- Error/rejection paths log and return instead of trying to return a boolean.
- Deferred queue failure is logged explicitly.
- Removed the active microStore compatibility generator from `platformio.ini`.
- Removed `MicroStoreCompat.generated.h`, microStore globals, and filesystem
  registration from `ReticulumService`.
- Retains explicit `RNS_USE_FS` / provisioning disablement in `RnsBuildConfig.h`.
- No intended radio/LXMF wire-format change from M1.1.3.

## Verification status

Source-audited and archive-checked here. A real PlatformIO build cannot be executed
in the assistant environment, so the user's PlatformIO build remains authoritative.
