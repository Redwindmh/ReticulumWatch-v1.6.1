# ReticulumWatch v1.3.0-build3 — contrast repair

## Problem

In v1.3.0-build2, the theme could apply a dark foreground to the Peer Details card or the thread history, yielding dark-on-black text. The screen root's inherited foreground was insufficient because LVGL child widgets can carry their own themed text styles.

## Scope

- `src/ui/WatchUI.cpp`: true-black backgrounds for thread history and Peer Details; explicit white foreground assigned recursively to the LVGL labels and widgets of these screens once during screen creation.
- Compose textarea receives black background/white foreground; the keyboard theme is intentionally excluded.
- No changes to LXMF, RNS, identity, peers, persistent data, messaging submission, radio, audio, or power logic.
- Peer Details → CHAT → Back returns to Peer Details; Peer Details → Back returns to the origin (Peers/Contacts).

## Hardware checklist

1. Open **Peers → Peer Details**; confirm the name, hash, hops, last-seen, verification, active-link, source and PIN state are white on black.
2. Toggle PIN and verify refreshed details remain white on black.
3. Open **Contacts → Peer Details** and confirm the same.
4. From Peer Details choose CHAT; check white conversation history and white button labels, black chat background and readable incoming/outgoing lines.
5. Press Back from chat (returns to Peer Details), then Back (returns to Contacts or Peers).
6. Open an existing conversation from Messages; check same black/white styling; scroll and use quick replies/VOICE/PTT as previously.
7. Open REPLY; text entered in the compose field should be white on black; watch-sized keyboard should be unchanged.
8. Reboot; verify contacts, PIN values, message history, delivery states and radio functionality.

## Verification boundary

The source preflight script can verify static contracts and protected-module hashes. It does not verify actual PlatformIO compilation or the on-watch LVGL rendering; these require the user's environment/hardware.
