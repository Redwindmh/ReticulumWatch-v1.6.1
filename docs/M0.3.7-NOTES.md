# M0.3.7 Notes — SCons callback fix

M0.3.6 reached the microStore compatibility pre-action, but the action itself failed before probing any headers:

```text
generate(["...ReticulumService.cpp.o"], ["...ReticulumService.cpp"])
TypeError: generate() got an unexpected keyword argument 'env'
```

PlatformIO/SCons invokes Python function actions with the conventional named arguments:

```python
(target, source, env)
```

M0.3.7 changes the pre-action callback to that exact signature:

```python
def generate_microstore_compat(target, source, env):
    ...
```

No microReticulum, radio, storage, identity, or UI behavior was otherwise changed. The purpose of this release is to finally execute the compatibility probe immediately before `ReticulumService.cpp` compiles and generate `MicroStoreCompat.generated.h` from the microStore headers PlatformIO actually installed.

Expected build output includes:

```text
[rw-microstore] probing installed microStore API
[rw-microstore] libdeps root: ...
[rw-microstore] Noop header: ...
[rw-microstore] FileSystem header: ...
[rw-microstore] detected: ...
[rw-microstore] FileSystem(FileSystemImpl*): yes|no
[rw-microstore] generated: .../MicroStoreCompat.generated.h
```
