# M1.2.1 — first watch-native messenger slice

M1.1.6 is retained as the immutable interoperability baseline. M1.2.1 is the
first feature iteration built on top of that proven receive path.

## User-facing changes

- Replaces the diagnostics-first home screen with a persistent message inbox.
- Shows the twelve newest messages in a vertically scrollable inbox and preserves older records on flash.
- Tap a message to open a scrollable detail view.
- Incoming and outgoing messages are shown in one chronological history.
- Adds a 220-character LVGL touch-keyboard composer.
- Adds `REPLY` / `SEND MORE` when the peer's incoming Reticulum Link is still active.
- Keeps user-triggered `lxmf.delivery` announce via the `ANN` button.

## LXMF transmit path

M1.2.1 intentionally starts with the smallest reliable outbound surface:
replies over a live incoming Reticulum Link. It does **not** yet create a new
path or outbound Link to an offline/previous peer.

For a reply it constructs the canonical current LXMF wire:

1. MessagePack payload `[timestamp, title, content, fields]`.
2. `hashed_part = destination_hash + source_hash + packed_payload`.
3. `message_id = SHA256(hashed_part)`.
4. `signature = Ed25519.sign(hashed_part + message_id)` using the watch identity.
5. Full Link payload is `destination_hash + source_hash + signature + packed_payload`.
6. The complete wire is sent with `RNS::Packet(active_link, wire).send()`.

The 220-character composer limit keeps the complete message below the active
Link MDU with room for LXMF metadata.

## Persistence

- New history records use `LMX2` and add destination hash plus an outgoing flag.
- Existing `LMX1` records from M1.1.x are read without migration or deletion.
- The existing `/lxmf/inbox/%08lu.lxm` sequence remains the chronological store.

## Trust and delivery state

M1.2.1 also corrects a latent M1.1.6 parser error: RatSpeak `Bytes::mid(begin, len)`
uses a length for its second parameter. M1.1.6 accidentally requested 32 bytes
for the source-hash slice and 96 bytes for the signature slice. Text still decoded
because the MessagePack payload begins at byte 96, but identity recall and the
computed message ID were wrong. M1.2.1 slices the canonical 16/16/64-byte prefix.

Incoming LXMF signatures are validated when `RNS::Identity::recall()` already
knows the sender identity. Otherwise the message remains `UNVERIFIED` instead
of manufacturing trust.

The pinned RatSpeak microReticulum commit still contains an incomplete Link
packet receipt validator. M1.2.1 therefore reports successful local send over
the encrypted Link, but does not claim a remote `DELIVERED` state.

## Deliberately deferred

- Starting a brand-new conversation from peer announces.
- Persistent contacts/peer directory.
- Path requests and outbound Link establishment after the original Link closes.
- Reliable delivered/read state.
- Large LXMF Resources, attachments, BLE/USB RNode mode.

These belong in the next messaging iterations after M1.2.1 is proven on-device.
