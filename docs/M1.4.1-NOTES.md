# M1.4.1 — security-rebase compile correction

## Why this patch exists

The first M1.4.0 PlatformIO build failed in `src/reticulum/RnsNoopFileSystem.h` while compiling `ReticulumService.cpp`. The actual dependency graph resolved `microReticulum @ 0.5.0` with `microStore @ 0.1.7`; that package did not provide the `microStore::Adapters` namespace used by the M1.4.0 application shim.

The build log contained three `error:` lines and all three were repetitions of the same compile error from the same translation unit. No second compiler-error family was present.

## Fix

M1.4.1 removes the application-level `RnsNoopFileSystem` shim and removes the `RNS::Utilities::OS::register_filesystem(...)` call. This is intentional, not a fallback adapter guess:

- `RNS_USE_FS` is force-disabled by `src/config/RnsBuildConfig.h`;
- `RNS_USE_PROVISIONING` remains disabled;
- ReticulumWatch already owns its permanent application identity and LXMF history through `StorageService` on the dedicated FFat partition;
- therefore this milestone has no reason to instantiate a microStore filesystem in application code.

## Unchanged M1.4 behavior

- `attermann/microReticulum @ 0.5.0` remains the security-rebase dependency.
- The fail-closed `Identity::validate()` positive/negative self-test remains.
- Explicit `UNKNOWN` / `KNOWN` / `VERIFIED` / `FAILED` trust states remain.
- Historical incoming verification claims are still downgraded rather than inherited.
- M1.3 independent path-request/opportunistic sending remains.
- Radio profile, RNode framing, split-packet logic, storage format/CRC/retention, UI accessibility changes, and deferred weak haptics are unchanged.

## Test

Run a clean dependency build once:

```bash
pio run -t fullclean
pio run -e twatch_s3_16mb
```

If the build succeeds, flash without erasing the Reticulum partition and perform the M1.4 acceptance sequence from the README.

## Verification status

Archive integrity and source-diff audits are performed in the assistant environment. PlatformIO is unavailable there, so M1.4.1 is not PlatformIO build-verified until the user's real build succeeds.
