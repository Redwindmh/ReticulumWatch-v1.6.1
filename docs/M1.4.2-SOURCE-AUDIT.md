# M1.4.2 source audit

Baseline: M1.4.1.

## Files intentionally changed

- `platformio.ini` — explicit `microStore @ 0.1.7` pin.
- `src/reticulum/RnsNoopFileSystem.h` — restored 0.1.7-compatible no-op filesystem adapter.
- `src/reticulum/ReticulumService.cpp` — initialize/register required filesystem before `Reticulum::start()` and fail closed on init failure.
- `src/main.cpp` — truthful critical-service boot gate.
- active version strings in `BuildConfig.h`, `RnsBuildConfig.h`, `RnsCompat.h`, `LxmfService.cpp`, and `WatchUI.cpp`.
- release notes/checklist/preflight documentation.

## Frozen baseline checks

`release_preflight.py` verifies SHA-256 hashes for:

- `src/radio/RadioService.cpp/.h`
- `src/reticulum/WatchLoRaInterface.cpp/.h`
- `src/storage/StorageService.cpp/.h`
- `src/config/RadioConfig.h`
- both partition CSV files

These hashes are the M1.4.1 values, since M1.4.0 necessarily adapted the Reticulum interface and storage trust metadata during the 0.5.0 security rebase.

## Regression checks added

The preflight fails if:

- a stale active version string remains;
- microReticulum 0.5.0 or microStore 0.1.7 pins disappear;
- the known-bad `microStore::Adapters::NoopFileSystem` spelling is reintroduced;
- filesystem initialization/registration is not ordered before `Reticulum::start()`;
- filesystem init failure is not propagated;
- top-level boot success is not gated by Reticulum + LXMF readiness;
- a frozen radio/storage/interface/partition file changes unexpectedly;
- partition validation fails.
