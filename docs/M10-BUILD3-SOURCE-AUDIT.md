# M10-build3 Source Audit

## Scope

M10-build3 is a narrow notification-cadence refinement on M10-build2. Runtime behaviour changes only in the synthesized **message receive** tone generated by `AudioService::alertStep()`.

## Changed functional source

- `src/audio/AudioService.cpp`
  - RX total alert duration changes from the prior ascending three-note sequence to a 595 ms six-beep sequence.
  - Cadence: three 55 ms beeps separated by 30 ms gaps, 145 ms group pause, then three more 55 ms beeps with 30 ms gaps.
  - Pitch: synthesized 1400 Hz square-wave tone.
  - TX alert cadence is unchanged.

## Non-functional/version files

- `src/config/BuildConfig.h` — version bumped to `M10-build3`.
- `src/ui/WatchUI.cpp` — startup diagnostic version string updated only.
- `README.md`, `docs/M10-BUILD3-NOTES.md`, `docs/MILESTONES.md`, `docs/MISTAKE-LEDGER.md` — release documentation.
- `scripts/release_preflight.py` — version/cadence/document guards.

## Frozen boundary

The accepted Reticulum/radio/config/partition boundary remains byte-identical and is verified by release preflight:

- `src/reticulum/ReticulumService.cpp/.h`
- `src/reticulum/WatchLoRaInterface.cpp/.h`
- `src/radio/RadioService.cpp/.h`
- `src/config/RnsBuildConfig.h`
- `src/config/RadioConfig.h`
- both partition CSVs

No LXMF wire, journal, storage failover, Codec2, clock discipline, peer-cache or Reticulum behaviour is changed by this build.

## Verification status

Static preflight, partition validation, source-manifest verification and fresh-ZIP integrity checks are release gates. They are not a substitute for a real PlatformIO build or hardware acceptance.
