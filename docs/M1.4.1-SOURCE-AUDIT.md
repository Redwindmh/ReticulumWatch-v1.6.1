# M1.4.1 source audit

## Baseline

Immutable source baseline: ReticulumWatch M1.4.0.

## Build-log diagnosis

The failed M1.4.0 PlatformIO run resolved:

- `microReticulum @ 0.5.0`
- `microStore @ 0.1.7`

and emitted only one compiler-error family: `microStore::Adapters` was not declared in the ReticulumWatch no-op filesystem shim.

## Intentionally changed source

- removed `src/reticulum/RnsNoopFileSystem.h`;
- `src/reticulum/ReticulumService.cpp` — removed the unnecessary no-op filesystem object/init/registration;
- active version strings/comments moved to M1.4.1;
- release documentation and mistake ledger updated.

## Security and protocol behavior intentionally unchanged

The M1.4.0 security changes remain intact: modern microReticulum dependency, fail-closed signature validation self-test, explicit trust states, historical-trust downgrade, and existing LXMF routing behavior.

## Frozen implementation files

The following are required to remain byte-identical to M1.4.0:

- `src/radio/RadioService.cpp`
- `src/radio/RadioService.h`
- `src/config/RadioConfig.h`
- `src/reticulum/WatchLoRaInterface.cpp`
- `src/reticulum/WatchLoRaInterface.h`
- `src/storage/StorageService.cpp`
- `src/storage/StorageService.h`
- both partition CSV files
- `platformio.ini`
- `docs/MASTER-BUILD-PLAN.md`

`LxmfService.cpp` and UI/main files differ only in active version text from M1.4.0.

## Verification limitation

The assistant environment does not have PlatformIO. Archive/source/static checks do not replace the user's ESP32-S3 PlatformIO compile, flash, and runtime validation.
