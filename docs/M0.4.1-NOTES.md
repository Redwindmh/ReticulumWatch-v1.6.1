## Scope

- Keep the proven M0.3.9 storage, identity, UI and microReticulum bootstrap.
- Configure an explicit LoRa receive profile.
- Use RadioLib's DIO1 packet-received interrupt; the ISR only sets a flag.
- Read frames in the main loop and decode RNode radio framing.
- Reassemble split payloads up to the Reticulum/RNode 508-byte MTU.
- Inject complete Reticulum payloads through a microReticulum `InterfaceImpl`.
- Set the interface to `_IN=true`, `_OUT=false`.
- Satisfy microReticulum's required `send_outgoing()` virtual with a defensive no-op; it never calls the radio.
- Do not announce, transmit, or expose a radio TX API.

## Default RX profile

`src/config/RadioConfig.h` contains all defaults:

- frequency: 920.600 MHz
- bandwidth: 125 kHz
- spreading factor: 8
- coding rate: 4/5
- LoRa sync word: 0x12 (private)
- preamble: 18 symbols
- explicit header
- 2-byte LoRa CRC

These values are only a starting receive profile. The external RNode used for a
test must use matching RF parameters. M0.4.1 does not authorize or initiate RF
transmission.

## RNode framing implemented

M0.4.1 implements the on-air framing behavior used by RNode firmware:

- physical LoRa MTU: 255 bytes
- byte 0: RNode framing header
- upper nibble: 4-bit packet sequence
- bit 0: split flag
- remaining low-nibble bits: reserved and rejected in this milestone
- single-frame Reticulum payload: up to 254 bytes
- split Reticulum payload: two physical frames with the same sequence, up to
  508 bytes total

A 3-second timeout clears an abandoned split reassembly. This is a watch-side
robustness measure; it does not alter received wire bytes.

## Expected startup

```text
[radio] RX profile 920.600 MHz BW=125 kHz SF=8 CR=4/5 sync=0x12 preamble=18
[radio] RNode framing RX enabled: 1-byte header, MTU=508, split reassembly active
[radio] SX1262 interrupt RX started; M0.4.1 contains NO radio transmit path
[rns] registered receive-only TWatchSX1262RX interface MTU=508 ...
[rns] Reticulum core started
[rns] loaded persistent 64-byte identity from /rns/identity.key
```

When a compatible frame arrives:

```text
[radio:rx] PHY #1 len=... payload=... seq=... split=... RSSI=... SNR=...
[radio:rx] complete Reticulum payload #1: ... bytes RSSI=... SNR=...
[rns:rx] injecting SX1262 payload #1: ... bytes
```

If microReticulum accepts the packet through Transport, the callback also logs:

```text
[rns:rx] accepted packet #1: ... bytes
```

## Acceptance

1. Firmware boots without changing the persistent identity/destination hashes.
2. SX1262 enters interrupt-driven receive mode without any transmission.
3. With no matching transmitter, PHY/PKT/RNS counters remain zero without
   instability.
4. With a compatible external RNode, physical frame counters increase.
5. RNode-framed packets are reassembled and injected into microReticulum.
6. Valid Reticulum packets reach the RNS receive callback.
