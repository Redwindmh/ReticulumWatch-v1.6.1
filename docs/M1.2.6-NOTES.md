# M1.2.6 — watch-sized composer keyboard

## Major milestone

Still **M1 — LXMF Messaging Core**. This is a requested UI usability patch on top of the hardware-proven M1.2.5 persistence/send/receive baseline; it is not a new conceptual milestone.

The master plan explicitly treats the touchscreen keyboard as a major watch UX feature, but this patch only improves the already-existing prototype composer while networking work remains in M1.

## Why change the keyboard

The LVGL stock keyboard is desktop/phone-oriented and its lower-case map can place roughly twelve buttons across a row. At 240 px wide that gives the T-Watch narrow touch targets even though the keyboard otherwise renders cleanly.

Rather than replacing LVGL or inventing a new input subsystem, M1.2.6 uses LVGL's supported custom keyboard-map interface. This preserves:

- the current keyboard visual language;
- textarea integration;
- built-in mode switching;
- cursor behavior;
- backspace behavior;
- future LVGL styling compatibility.

## Watch layout

The character maps are wrapped into seven-column rows. This intentionally sacrifices desktop-QWERTY row geometry for larger targets while preserving QWERTY letter order.

The keyboard is 230x146 px, bottom-aligned. The text area is 228x44 px at y=31 and the status line is at y=77.

The M1.2.2 geometry lesson remains in force: do not replace the explicit bottom alignment with an apparently absolute `lv_obj_set_pos()` call after `lv_keyboard_create()`.

## Modes

- lower case: 26 letters plus period/comma;
- upper case: same geometry;
- special: digits and common punctuation;
- `ABC`, `abc`, `1#` use LVGL's built-in mode switching semantics;
- left/right, space and backspace remain present in the bottom control row.

Character-key popovers are enabled to provide touch confirmation.

## Known-good behavior deliberately untouched

No functional changes to:

- storage journal or retention;
- LMX3 CRC/state;
- dedupe;
- LoRa/RNode framing;
- Reticulum interface/destination/Link behavior;
- LXMF parser/wire construction;
- signed reply transmission;
- on-screen restart.

## Next conceptual work

After this UI patch is hardware-accepted, return to the master roadmap rather than extending keyboard work indefinitely. The next substantive protocol target remains the uncompleted portion of **M1.3 — Outgoing LXMF**: sending without requiring an already-active incoming reply Link, followed by honest delivery/failure state work when the receipt path can support it.
