# M0.5 — Controlled Reticulum transmit + announce

M0.5 is the first Reticulum Watch milestone with an RF transmit path. It builds
on the proven M0.4.1 receive implementation and keeps TX deliberately narrow:
only packets emitted during the explicit microReticulum TX gate can reach
the SX1262, and the UI exposes one explicit action: **SEND ANNOUNCE**.

## Scope

- Preserve persistent 64-byte watch identity and `reticulum_watch.node` destination.
- Keep the LoRa `InterfaceImpl` at `_OUT=false` while idle and open it only around an explicit user-requested announce.
- Route `send_outgoing(const RNS::Bytes&)` to `RadioService`.
- Implement RNode-compatible TX framing for 1..508-byte Reticulum packets.
- Return the SX1262 to interrupt-driven RX immediately after every TX attempt.
- Add TX/RNS/announce counters and serial diagnostics.
- Add a user-triggered `SEND ANNOUNCE` button.
- Do **not** add periodic announces, background TX, Transport mode, LXMF, or a
  generic raw-radio transmit UI in this milestone.

## RNode TX framing

M0.5 mirrors the current RNode on-air framing behavior:

- physical LoRa MTU: 255 bytes
- byte 0: framing header
- bits 7..4: 4-bit sequence value
- bit 0: split flag
- Reticulum payload <=254 bytes: one physical frame
- payload 255..508 bytes: two frames with the same sequence + split flag
- first split frame carries 254 Reticulum bytes
- second split frame carries the remainder

The receive-side reassembly from M0.4.1 remains unchanged.

## TX execution model

The LVGL button does not transmit directly. It calls `requestAnnounce()`, which
only sets an application flag. `ReticulumService::loop()` consumes that flag and
calls `destination_.announce()` from normal task context.

`ReticulumService` opens `_OUT` immediately before the announce. microReticulum
then selects `TWatchSX1262`, calls its `send_outgoing()`, and the interface
performs a synchronous RadioLib transmission. The gate closes as soon as the
announce call returns. The packet-received ISR
is detached during TX, then restored before returning.

## Default profile

- 920.600 MHz
- 125 kHz bandwidth
- SF8
- CR 4/5
- sync word 0x12
- 18-symbol preamble
- explicit LoRa header
- 2-byte CRC
- TX power 10 dBm

All values remain compile-time overrides in `src/config/RadioConfig.h`.

## Expected first announce

Press **SEND ANNOUNCE** once. A successful path should resemble:

```text
[ui] SEND ANNOUNCE pressed; request queued
[rns:tx] announce request #1 queued for 4234af254feb0299f544969b7c6392f0
[rns:tx] emitting announce for 4234af254feb0299f544969b7c6392f0
[rns:tx] interface handing ... bytes to SX1262
[radio:tx] Reticulum request #1 len=... seq=... split=no
[radio:tx] PHY #1 len=... seq=... split=no part=1 OK
[radio:tx] complete Reticulum payload #1: ... bytes
[radio:tx] SX1262 returned to interrupt RX mode
[rns:tx] accepted outgoing packet #1: ... bytes
[rns:tx] Destination::announce() returned
```

The exact ordering of the final two RNS lines can vary with microReticulum's
callback path.

## Acceptance

1. M0.5 builds and boots with the same persistent identity and destination hash.
2. Existing RX interoperability still works with the gated TX implementation.
3. No RF TX occurs at boot or periodically while idle.
4. One press of `SEND ANNOUNCE` results in exactly one Reticulum announce path.
5. The external Reticulum/RNode peer learns a path to the watch destination.
6. The watch returns to RX and can receive another packet after announcing.
7. A >254-byte outgoing Reticulum packet, when introduced in a later test, uses
   the same two-frame RNode split framing already implemented here.

## TX gate invariant

While idle, the registered LoRa interface remains `_IN=true`, `_OUT=false`.
`requestAnnounce()` does not open the gate. The gate is opened only in normal
service-loop context immediately before `Destination::announce()`, and is closed
again immediately afterward, including after caught exceptions. This prevents
ordinary inbound path requests from silently turning M0.5 into an autonomous
transmitter before that behavior is intentionally introduced in a later milestone.
