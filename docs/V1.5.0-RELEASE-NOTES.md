# ReticulumWatch v1.5.0 release notes

## Scope

Audio/PTT usability refinement on top of the hardware-accepted v1.4.0 baseline. No Reticulum packet, LXMF field, radio, persistence-format, or Codec2 mode change is introduced.

## User-visible changes

### Conversation PTT status
A compact white-on-black line above the conversation action buttons now reports voice state:

- `Hold PTT to record | release to send` when an active Link is available;
- `PTT needs active Link | VOICE can preview locally` when it is not;
- live `REC x.xs / 3.0s | release sends`;
- `Encoding voice...`;
- `Sending voice...`;
- playback preparation/progress;
- final submission/error status.

The PTT button itself changes to `REC` while held and is disabled when the active-Link prerequisite is not satisfied.

### Voice composer
The existing VOICE screen now reports recording and playback progress live and presents the intended workflow more clearly: RECORD, optional PLAY, SEND.

### Playback progress
`AudioService::playbackMs()` exposes only the current local playback offset for UI display. It does not change audio scheduling or data.

## Explicit non-goals

- no live voice streaming;
- no LXST claim;
- no Sideband wire-format experiment;
- no radio duty-cycle changes;
- no voice delivery-state inflation: Link sends remain conservatively submitted where proof validation is unavailable.
