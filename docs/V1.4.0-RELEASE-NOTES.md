# ReticulumWatch v1.4.0 Release Notes

v1.4.0 begins the post-1.0 **Power & Endurance** phase. It is intentionally conservative: connected standby remains an always-listening Reticulum state, while unnecessary diagnostic/UI work around that state is reduced.

## Added

- Session power telemetry on **Settings → Watch → Power**:
  - active minutes;
  - connected-standby minutes;
  - standby entry count;
  - crown wake count;
  - lift wake count.
- Sparse v1.4 standby heartbeat for field verification.

## Efficiency changes

- Removed the previous 1 Hz diagnostic BMA423 accelerometer read while the display is asleep. Lift-to-wake continues to use the BMA423 hardware feature engine + GPIO14 IRQ path.
- Reduced non-actionable BMA423 IRQ status logging to at most once per 15 seconds; real tilt/wakeup events still log immediately.
- Reduced standby heartbeat from once per second to once per 60 seconds, without an accelerometer I2C sample.
- Reduced UI inbox/notification polling from 350 ms to 1200 ms only while the display is asleep. Reticulum/LXMF processing remains active independently.

## Deliberately unchanged

- SX1262 radio profile and framing;
- Reticulum startup/interface behavior;
- LXMF encoding, retry, path-request and Link behavior;
- message storage formats;
- v1.2 Sending message UX;
- v1.3 Peer Details/navigation/high-contrast chat UI;
- BMA423 feature-engine wake authority;
- crown wake;
- audio/Codec2/PTT.

## Connectivity contract

v1.4.0 does **not** enter ESP deep sleep or duty-cycle the radio. Display-off mode remains CONNECTED STANDBY: LoRa + Reticulum stay online.
