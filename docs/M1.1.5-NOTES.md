# M1.1.5 — Required microStore filesystem registration

M1.1.4 built and flashed, but Reticulum aborted at runtime with:

`FileSystem has not been registered`

The RatSpeak microReticulum lineage still requires an `RNS::Utilities::OS`
filesystem registration before `Reticulum::start()`, even when internal RNS
persistence is disabled.

M1.1.5 restores the exact no-op storage contract that was already proven on
ReticulumWatch M0.x/M1.0.x:

- explicitly depends on `attermann/microStore @ 0.1.7`;
- enables `USTORE_USE_NOOPFS`;
- constructs `microStore::Adapters::NoopFileSystem()`;
- calls `RNS::Utilities::OS::register_filesystem()` before `Reticulum::start()`;
- treats the no-op backend's `init()==false` as non-fatal;
- leaves application identity and LXMF inbox persistence on the existing FFat
  `StorageService`.

No RF framing or LXMF wire-format behavior is changed in this patch.
