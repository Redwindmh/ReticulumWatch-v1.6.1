# M1.2.5 source audit

## Version discipline

M1.2.4 remains immutable. This patch is issued as M1.2.5.

## Major milestone

M1.2 — Persistent Inbox and Message History.

## Exact source changes

Functional storage changes are limited to:

- `src/storage/StorageService.h`
- `src/storage/StorageService.cpp`

`src/lxmf/LxmfService.cpp` changes only:

1. version/log text;
2. incoming record state = `RECEIVED`;
3. outgoing successful local Link submission state = `SUBMITTED`.

Version/log-only changes also occur in `BuildConfig.h`, `main.cpp`, and `WatchUI.cpp`.

## Network baseline byte comparison

The following M1.2.5 files were SHA-256 compared to M1.2.4 and are byte-for-byte identical:

- `src/radio/RadioService.cpp`
- `src/radio/RadioService.h`
- `src/reticulum/ReticulumService.cpp`
- `src/reticulum/ReticulumService.h`
- `src/reticulum/WatchLoRaInterface.cpp`
- `src/reticulum/WatchLoRaInterface.h`
- `src/reticulum/RnsCompat.h`
- `src/reticulum/RnsNoopFileSystem.h`
- `src/config/RadioConfig.h`
- `src/config/RnsBuildConfig.h`
- `platformio.ini`

Therefore this patch does not intentionally alter the hardware-validated LoRa/Reticulum path or pinned dependency set.

## Storage safety review

- new records are LMX3 and CRC32 protected;
- old LMX1/LMX2 records remain readable;
- new authoritative record writes use temp + rename;
- existing final history path is never overwritten;
- interrupted temp file is discarded at boot;
- corrupt active records are quarantined rather than treated as valid;
- active history is bounded at 256 records;
- corrupt quarantine is bounded at 16 records;
- message-ID marker writes use temp + rename;
- malformed marker content is not accepted as a valid index solely because a file exists;
- derived sequence/index failures remain recoverable from retained journal records.

## Local compile audit

`StorageService.cpp` was passed through:

```text
g++ -std=gnu++17 -fsyntax-only
```

against local lightweight Arduino/FFat/FS stubs including the `remove()` and `rename()` APIs used by the patch. The syntax-only compile completed successfully.

This is not equivalent to a PlatformIO build and must not be described as one.

## PlatformIO status

PlatformIO is unavailable in the artifact-generation environment. Hardware/toolchain build verification therefore remains pending the user's `pio run`.
