# M1.2.5 — bounded, CRC-protected LXMF history

## Major milestone

Still **M1 — LXMF Messaging Core**, specifically **M1.2 — Persistent Inbox and Message History**.

This is a patch release, not a new conceptual milestone.

## Proven input baseline

M1.2.4 hardware validation proved the confirmation-gated software restart and the second-boot persistence acceptance:

- boot count advanced;
- five existing history records survived;
- zero message-ID markers needed rebuilding on the second boot;
- permanent application identity remained stable;
- latest message restoration and durable dedupe lookup both succeeded.

## Acceptance criterion targeted by this patch

Close the remaining storage-integrity gaps from the master plan without touching the proven radio/Reticulum wire behavior:

- bounded storage / cleanup policy;
- explicit persisted delivery-state model;
- stronger record-integrity checking;
- corruption handling;
- power-loss-safe authoritative history writes.

## New LMX3 record

LMX3 preserves the LMX2 fields and adds:

```text
uint8_t deliveryState
uint8_t reserved[3]
uint32_t crc32
```

The CRC32 is IEEE CRC-32 over all bytes preceding the `crc32` field in the packed record.

Compatibility:

- LMX1: readable; mapped to incoming `RECEIVED`;
- LMX2 incoming: readable; mapped to `RECEIVED`;
- LMX2 outgoing: readable; mapped to `SUBMITTED`;
- LMX3: full CRC validation and explicit state.

No mass rewrite/migration of old records occurs at boot.

## Delivery-state semantics

```text
UNKNOWN
RECEIVED
SUBMITTED
DELIVERED
FAILED
```

Current runtime writes only:

- `RECEIVED` for incoming LXMF;
- `SUBMITTED` for watch-originated messages accepted by `Packet::send()`.

`DELIVERED` is intentionally not emitted because the pinned fork's Link proof receipt validation is not yet trustworthy enough to support that user-visible claim.

## Atomic authoritative record commit

New records are written to:

```text
/lxmf/inbox/.write.tmp
```

then renamed to the final sequence path only after the complete LMX3 record has been written and flushed.

A stale temp file found at boot is discarded before journal recovery.

The `.lxm` record remains authoritative. `message_count.bin` and message-ID markers remain rebuildable derived metadata.

## Corruption quarantine

During boot audit, an unreadable record is moved out of the active journal to `/lxmf/corrupt/`.

This prevents a broken file from repeatedly occupying the active inbox while preserving a bounded forensic artifact.

The quarantine retains at most 16 corrupt artifacts.

## Retention policy

Normal active history keeps the newest 256 sequence slots. When the high sequence exceeds 256, records older than the retention window are deleted, along with message-ID markers whose recorded sequence is outside the window.

Sequence numbers are never compacted or renumbered.

## Known-good behavior deliberately untouched

No functional changes to:

- `RadioService`;
- `WatchLoRaInterface`;
- `ReticulumService`;
- radio configuration/framing;
- Link establishment;
- LXMF wire construction/parsing;
- UI geometry/navigation.

`LxmfService` only assigns persistence state and changes diagnostics/version strings.
