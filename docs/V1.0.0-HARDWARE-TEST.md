# ReticulumWatch v1.0.0 — Hardware Test Guide

This is the concise acceptance checklist for the stable release.

## 1. Boot and version

**What to look for on the watch**
- Watch face appears normally.
- Existing settings, identity and history remain present.
- Version shown in the UI should read `1.0.0` where version information is displayed.

**What to look for in serial**
- `Reticulum Watch 1.0.0 booting...`
- `[boot] 1.0.0 initialization complete`
- no `DEGRADED` line for Reticulum or LXMF.

## 2. Connected standby

Let the display time out naturally.

**Expected**
- display turns off;
- Reticulum remains online;
- sleeping glass taps do not wake the screen.

**Useful serial evidence**
- `[m4:power] connected standby: display asleep; Reticulum RX remains active`
- `[m12:power] standby mode=CONNECTED-IDLE`

## 3. Crown wake/toggle

With the display asleep, short-press the crown.

**Expected**
- display wakes immediately;
- another deliberate crown action follows the existing toggle behavior;
- selected brightness is restored.

## 4. Lift to Wake

Enable Lift to Wake in Settings, let the display sleep, then naturally raise the watch toward viewing position.

**Expected**
- display wakes from a normal wrist-lift;
- no need to touch the glass.

**Useful serial evidence**
- `tilt=YES` or `wakeup=YES`
- `[m12:motion] hardware lift event latched`
- `[m12:power] wake source=lift`

A slightly deliberate lift is acceptable for v1.0.0; sensitivity has deliberately not been altered from the hardware-accepted M13 path.

## 5. LXMF receive

Send a message to the watch from a known Reticulum/LXMF peer.

**Expected**
- message appears in the correct conversation;
- unread state increments when appropriate;
- notification/haptic behavior occurs;
- message persists after reopening the thread.

## 6. LXMF send

Reply from the watch, then also test a peer where an active Link is not already open if practical.

**Expected**
- normal active-Link reply works;
- opportunistic/path-request send still works for a known peer;
- remote client receives human-readable text;
- outgoing message is retained in history.

## 7. Reboot persistence

Use the software restart or power-cycle the watch.

**Expected**
- same Reticulum identity;
- settings preserved, including Lift to Wake choice and display timeout;
- message history/contact state preserved;
- no unexpected quarantine or index rebuild loop.

## 8. Audio regression

Open Audio and test local record/playback. If convenient, send one Codec2 voice message.

**Expected**
- local capture/playback works;
- text messaging remains usable afterward;
- audio failure, if encountered, must not take Reticulum/LXMF down.

## 9. Recovery console sanity

From serial, run:

`M11 STATUS`

**Expected**
- recovery console responds;
- filesystem statistics are sane;
- do **not** format storage merely for this test.

## Pass criteria

For a normal stable-release smoke test, report these six items explicitly:

1. boot/version: PASS/FAIL
2. crown wake: PASS/FAIL
3. lift wake: PASS/FAIL
4. sleeping touch does not wake: PASS/FAIL
5. LXMF receive/send: PASS/FAIL
6. reboot persistence: PASS/FAIL

If all six pass, v1.0.0 has passed the practical smoke test.
