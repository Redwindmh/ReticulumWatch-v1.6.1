# M0.3.5 notes

M0.3.4 failed before firmware compilation completed because PlatformIO resolved
an old `microStore` API despite a project-local `.pio` clean. The compiler saw
`FileSystem(FileSystemImpl*)` and no `microStore::Adapters` namespace.

M0.3.5 changes only the dependency acquisition/diagnostic boundary:

- `microStore` and `microReticulum` are fetched as GitHub source ZIP packages
  from the same upstream development line instead of VCS URLs.
- `scripts/check_microstore_api.py` reports the resolved NoopFileSystem header
  and rejects a legacy API before the long build begins.
- The Reticulum core/identity logic, zero-RF policy, fixed 240x240 UI, persistent
  watch identity storage, and gentler/debounced haptic diagnostic remain intact.

Once a matched pair builds and boots, replace the floating source-ZIP refs with
immutable commits/tags before advancing the milestone.
