# M1.3.0 source/API audit

## Baseline

Source baseline: immutable ReticulumWatch M1.2.7.

Pinned microReticulum:

```text
https://github.com/ratspeak/microReticulum.git#290a1336ebe05782c80a1debf8a8da0316a88ae7
```

## Exact pinned APIs checked

`src/Transport.h` at the pinned commit declares:

```cpp
static bool has_path(const Bytes& destination_hash);
static void request_path(const Bytes& destination_hash);
```

It also exposes the overload with interface/tag/recursive arguments, but M1.3.0 intentionally uses the one-argument overload.

`src/Destination.h` declares the OUT/SINGLE constructor used by the opportunistic sender:

```cpp
Destination(
    const Identity& identity,
    const Type::Destination::directions direction,
    const Type::Destination::types type,
    const char* app_name,
    const char* aspects
);
```

`src/Identity.h` declares:

```cpp
static Identity recall(const Bytes& destination_hash);
```

`src/Packet.h` declares:

```cpp
Packet(const Destination& destination, const Bytes& data, ...);
PacketReceipt send();
```

The pinned `Type.h` defines:

```cpp
RNS::Type::Packet::ENCRYPTED_MDU
```

which M1.3.0 uses as the opportunistic SINGLE-body size ceiling.

## LXMF wire audit

The opportunistic sender follows the established microReticulum LXMF pattern:

- build OUT/SINGLE `lxmf.delivery` destination from the recalled peer identity;
- hash/sign with destination hash + source hash + MsgPack payload;
- omit destination hash from the opportunistic LXMF body;
- construct `RNS::Packet(destination, body)` and send.

The sender additionally verifies that the recalled identity derives the exact destination hash selected from history before encrypting to it.

## Compile-risk audit

M1.3.0 introduces no new LVGL API use. The M1.2.7 keyboard source is preserved.

The changed `LxmfService.cpp` was compiled with `g++ -std=c++17 -fsyntax-only` against an API-shape stub matching the exact pinned signatures used by this change. This is a syntax/API-shape check, **not** a PlatformIO firmware build.
