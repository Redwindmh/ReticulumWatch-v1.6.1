# ReticulumWatch v1.4.0 Hardware Test

## 1. Boot

Expected serial:

```text
[boot] 1.4.0 initialization complete
[v1.4:power] manager ready: connected standby efficiency counters active
```

PASS: normal boot, Reticulum/LXMF ready, no unexpected DEGRADED state.

## 2. Connected-standby logging — NEW

Allow the display to time out with Lift to Wake enabled.

Expected:

- the old once-per-second `standby heartbeat ... accel=... x=... y=... z=...` flood is gone;
- a sparse line appears about once per minute:

```text
[v1.4:power] standby heartbeat cpu=running gpio=... irq_edges=... sensor_irq=armed
```

PASS: no 1 Hz accelerometer telemetry while asleep; sparse heartbeat only.

## 3. Reticulum receive while asleep — CRITICAL

With the display asleep, send one LXMF message to the watch from another node.

PASS:

- radio/LXMF receives the message;
- watch notification behavior remains functional;
- no manual wake is required before reception.

This proves v1.4 reduced surrounding work without disabling always-listening Reticulum.

## 4. Crown and lift wake regression

- Crown short press wakes the display.
- Put the watch back into standby and perform the accepted lift gesture.

Expected serial still includes:

```text
[m12:motion] hardware lift event latched
[m12:power] wake source=lift
```

PASS: both wake sources work as before.

## 5. Power screen counters — NEW

Open **Settings → Watch → Power**.

Verify the screen shows:

- session active minutes;
- standby minutes;
- standby entry count;
- crown wake count;
- lift wake count.

Exercise one crown wake and one lift wake, reopen the page, and verify the corresponding counters increase.

PASS: counters reflect the current boot session plausibly.

## 6. Messaging regression

Send and receive one normal text message.

PASS:

- `Sending message...` overlay still appears;
- outgoing message submits normally;
- incoming message is received;
- Peer Details/chat black-and-white styling remains intact.
