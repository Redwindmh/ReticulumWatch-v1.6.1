# Reticulum Watch M0.1.3 notes

## Purpose

M0.1.3 fixes a boot-time hang discovered after M0.1.2 successfully built and
flashed on a 16 MB T-Watch S3.

## Root cause

`LilyGoWatch2022::begin()` invokes LilyGoLib's `setupMSC()` before PMU and
display initialization unless `NO_INIT_FATFS` is supplied. `setupMSC()` uses
LilyGoLib's FFat-backed USB mass-storage path. Reticulum Watch intentionally
uses a custom FAT partition labelled `reticulum`, while LilyGoLib's default
FFat path expects its own `ffat` partition. The result was a repeated
`setupMSC(): FFAT INIT FAILED!` loop before the display could be initialized.

## M0.1.3 behavior

The hardware abstraction now calls LilyGoLib with these initialization paths
disabled:

- `NO_INIT_FATFS` — Reticulum Watch owns persistent storage and will mount it
  explicitly in the storage service.
- `NO_HW_LORA` — Reticulum Watch owns SX1262 configuration in the radio
  service; M0.1 does not transmit.
- `NO_HW_GPS` — GPS is not part of M0.1 bring-up and the non-Plus watch does
  not require it.
- `NO_HW_MIC` — microphone/amplifier initialization is deferred until the
  later audio milestone.

LilyGoLib still initializes the PMU, display, touch controller, BMA423 sensor,
RTC, and haptic driver.

Additional serial markers were added before and after LilyGo board
initialization so any future bring-up stall can be localized immediately.
