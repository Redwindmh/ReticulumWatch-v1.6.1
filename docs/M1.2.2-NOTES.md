# M1.2.2 — compose-screen geometry correction

M1.2.1 built, flashed, received LXMF messages, persisted history, and learned a live reply route, but the first on-device compose screen exposed two 240x240 layout defects: the stock LVGL keyboard appeared mostly below the display, and the centered peer heading collided with the SEND button.

## Root cause

`lv_keyboard_create()` gives the keyboard `LV_ALIGN_BOTTOM_MID` in its constructor. M1.2.1 then called `lv_obj_set_pos(keyboard, 0, 91)`. With the keyboard still bottom-aligned, those coordinates act as alignment offsets rather than a clean absolute top-left placement, pushing the keyboard down by roughly the observed amount.

## M1.2.2 correction

- Keep the stock keyboard, but size it to 230x128 and explicitly align it to `LV_ALIGN_BOTTOM_MID` with zero offset.
- Compact keyboard padding to 2 px.
- Reserve y=0..28 for Back / peer / Send.
- Reserve y=34..84 for the textarea.
- Put the status line at y=86.
- Put the keyboard in the bottom 128 px.
- Constrain the heading to a 128 px region between the Back and Send buttons and display `TO <10 hex chars>` instead of the longer `REPLY <12 hex chars>`.

No Reticulum, radio, LXMF wire, identity, or storage behavior is changed.

## Verification status

Source/layout audited and archive-integrity tested. Not marked PlatformIO build-verified until a complete build succeeds on the target toolchain.
