# M0.3.6 Notes — microStore API compatibility

M0.3.5 proved that changing dependency URLs did not solve the build failure. The
compiler consistently exposed `microStore::FileSystem(FileSystemImpl*)` while
our source hard-coded `microStore::Adapters::NoopFileSystem()`.

M0.3.6 removes that hard-coded assumption. A PlatformIO pre-action runs
immediately before `ReticulumService.cpp` is compiled, reads the actual
`microStore/FileSystem.h` and `microStore/Adapters/NoopFileSystem.h` installed in
`.pio/libdeps`, and generates `src/config/MicroStoreCompat.generated.h` for the
API shape it detects.

The build prints `[rw-microstore]` diagnostics with:

- the exact headers selected;
- the detected NoopFileSystem API family;
- whether `FileSystem(FileSystemImpl*)` exists;
- any adapter feature macros found in the installed header.

This milestone still registers only a no-op RNS internal store. The watch's
permanent 64-byte Reticulum identity remains persisted by `StorageService` in
the dedicated `/reticulum` FAT partition. No RF transmission is enabled.
