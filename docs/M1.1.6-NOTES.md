# M1.1.6 — RNS-native filesystem compatibility correction

M1.1.5 attempted to restore the filesystem registration required by the pinned
RatSpeak microReticulum commit `290a1336ebe05782c80a1debf8a8da0316a88ae7`, but
it passed `microStore::FileSystem` to `RNS::Utilities::OS::register_filesystem()`.
The exact pinned fork declares that API as:

```cpp
static void register_filesystem(RNS::FileSystem &filesystem)
```

so M1.1.5 fails to compile with a type-conversion error.

M1.1.6 corrects only that compatibility boundary:

- adds a small local `RnsNoopFileSystemImpl` implementing the fork's
  `RNS::FileSystemImpl` contract;
- registers an `RNS::FileSystem` backed by that no-op implementation before
  `Reticulum::start()`;
- removes the incompatible `microStore 0.1.7` dependency from this path;
- keeps `RNS_USE_FS` and RNS internal persistence disabled;
- leaves ReticulumWatch identity and inbox persistence on the existing FFat
  `StorageService`;
- leaves RF framing, Link behavior, LXMF metadata, and protocol semantics
  unchanged from M1.1.5.

## Verification status

The correction is source-audited against the exact pinned fork headers. The
archive is **not claimed build-verified** until PlatformIO completes successfully
against the user's normal toolchain/dependency cache.
