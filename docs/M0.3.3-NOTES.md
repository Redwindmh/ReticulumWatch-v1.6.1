# M0.3.3 notes

M0.3.3 fixes the Reticulum startup boundary discovered on real T-Watch S3 hardware.

## Observed M0.3.1 failure

The Reticulum Watch FAT partition mounted and remained persistent, but attempting to
`chdir("/reticulum/rns")` failed before microStore initialization. Arduino's FFat
filesystem wrapper and ESP-IDF's process-wide POSIX current-directory semantics are
not interchangeable abstractions, so relying on `chdir()` was incorrect.

## M0.3.3 strategy

For this milestone there are two distinct persistence responsibilities:

1. **Node identity persistence** — required now and already proven. `StorageService`
   stores the 64-byte private Reticulum identity in `/rns/identity.key` on the
   dedicated FAT partition.
2. **microReticulum internal persistence** — path table, known-destination table,
   packet hash list and provisioning state. This is useful later but is not needed
   to prove the Reticulum core and stable node identity.

M0.3.3 therefore does **not instantiate microStore at all**. A small build-config
header is force-included for every translation unit and explicitly undefines
`RNS_USE_FS` and `RNS_USE_PROVISIONING` before microReticulum is compiled. This
keeps the core stack and `RNS::Identity` active while omitting the internal path,
known-destination, packet-hash and provisioning persistence layers. A rooted
persistent adapter will be added before transport-node features depend on those
tables.

## RF policy

The SX1262 remains initialized but in standby. M0.3.3 transmits no RF packets.
