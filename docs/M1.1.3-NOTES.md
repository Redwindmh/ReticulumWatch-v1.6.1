# M1.1.3 — pinned-fork API compatibility correction

M1.1.3 follows M1.1.2 without overwriting it.

## Why M1.1.2 failed

PlatformIO successfully resolved the RatSpeak microReticulum fork and its
Crypto/ArduinoJson/MsgPack dependencies, but the application included
`<microReticulum.h>`. The pinned RatSpeak commit reports microReticulum 0.2.10;
the umbrella header was introduced later in upstream microReticulum 0.4.0.
The compile therefore failed before reaching the application code.

## Corrections

- Added `src/reticulum/RnsCompat.h`, which includes the individual 0.2.x public
  Reticulum headers instead of the later umbrella header.
- Removed the speculative `LXMFMessage.h` dependency and restored the bounded,
  known project MsgPack LXMF decoder. It now accepts the full LXMF wire shape
  used by both reconstructed opportunistic delivery and direct Link delivery.
- Restored the older `InterfaceImpl::send_outgoing(const Bytes&) -> bool`
  contract used by the pre-umbrella microReticulum line.
- Removed speculative `start()/stop()` interface overrides.
- Removed the speculative RNS FileSystemImpl adapter. For this interoperability
  milestone, RNS internal persistence is disabled and the compile-proven no-op
  filesystem compatibility generator is used. The watch identity and LXMF
  inbox still persist on the dedicated FFat partition through StorageService.
- Retains M1.1's important interoperability behavior: one canonical
  `lxmf.delivery` destination, `PROVE_ALL`, incoming Links, MCU-safe LXMF
  announce metadata with no compression capability, and explicit SX1262 RX
  re-arming after RX/TX.

## Build status

This archive is source/API-audited but not locally PlatformIO-built in the
assistant execution environment. Run `pio run -e twatch_s3_16mb` first; only
run the upload target after a successful build.
