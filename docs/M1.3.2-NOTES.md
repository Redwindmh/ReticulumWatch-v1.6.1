# M1.3.2 — Button/key haptics and visible composer cursor

## Why this patch exists

M1.3.1 hardware testing confirmed that the enlarged Back controls and the seven-column watch keyboard are substantially easier to use. The remaining tactile/typing usability gaps were:

- no feedback confirming that a specific on-screen control was actually activated;
- no reliably visible insertion cursor in the composer, making spaces and cursor movement hard to judge.

M1.3.2 remains a narrow M1.3 usability patch before the planned M1.4 protocol/security work.

## Haptic policy

Haptics are attached to **semantic controls**, not the touchscreen/root object:

- all normal `makeButton()` buttons vibrate only on `LV_EVENT_CLICKED`;
- inbox message rows vibrate only on their button `LV_EVENT_CLICKED`;
- the keyboard vibrates only on `LV_EVENT_VALUE_CHANGED`, which the LVGL button-matrix emits for an actual key interaction;
- tapping empty/background areas, scrolling, and tapping the textarea itself do not intentionally trigger haptics;
- disabled buttons do not intentionally trigger haptics.

`WatchUI` does not directly operate the DRV2605. It requests `WatchHardware::tapHaptic()`, preserving centralized hardware ownership.

The UI tap waveform uses DRV2605 effect 6 (Sharp Click, 30%) with a 35 ms duplicate-event guard. The existing `WatchHardware::vibrate()` notification/system effect remains separate and stronger.

## Composer cursor

The composer styles `LV_PART_CURSOR` as a 2 px left-border caret using the textarea's current text colour and a 400 ms blink duration.

ReticulumWatch also explicitly applies `LV_STATE_FOCUSED` to the textarea after attaching the keyboard. This is intentional compatibility handling for the exact LVGL 9.4.0 dependency: the tagged 9.4.0 `lv_keyboard_set_textarea()` implementation does not reliably apply focus to the assigned textarea, which can leave the cursor invisible.

## Intentionally unchanged

No functional changes were made to:

- `LxmfService` routing/wire behavior (version log text only);
- `StorageService` / LMX3;
- `RadioService`;
- `WatchLoRaInterface`;
- `ReticulumService`;
- radio profile;
- Reticulum identity persistence;
- keyboard geometry/maps;
- M1.3 independent path-request/opportunistic send logic.

## Acceptance test

1. Build/flash without erasing the Reticulum partition.
2. Open a message and press Back; confirm one light click and normal navigation.
3. Tap empty screen/background space; confirm no haptic.
4. Open the composer and type `A B C` (including spaces); confirm one light haptic per actual keyboard key.
5. Use left/right cursor keys and confirm haptic feedback plus a clearly visible caret moving through the text.
6. Tap the textarea/background without a button activation; confirm no button haptic.
7. Send the message and confirm remote reception.
8. Receive one message and confirm the inbox/message flow still works.
