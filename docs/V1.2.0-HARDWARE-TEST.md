# ReticulumWatch v1.2.0 — Hardware Test Guide

## New feature under test

### 1. Typed-message send popup

1. Open a peer conversation.
2. Tap **REPLY**, enter a short message, and tap **SEND**.
3. Immediately look at the display.

PASS:

- a centered modal appears saying **Sending message...**;
- second line says **Submitting to Reticulum**;
- underlying controls cannot be tapped while the modal is visible;
- after local submission, the conversation returns and the outgoing message is visible;
- serial contains `[v1.2:ux] sending-message overlay shown` and then `submission accepted`;
- normal LXMF TX diagnostics follow.

FAIL:

- no popup appears;
- popup appears only after the radio send has already completed;
- the watch remains stuck behind the modal;
- duplicate messages are generated by extra taps;
- the UI says Delivered without actual delivery evidence.

### 2. Thread quick replies

If quick replies are configured, tap each one from a conversation.

PASS: the same **Sending message...** modal appears, one message is submitted, and the thread returns.

### 3. Notification quick reply

Receive an LXMF message while the notification popup is available, then use a configured quick reply.

PASS: the same modal appears and, after submission, the watch returns to the watch face.

## Regression checks

### 4. Incoming LXMF
Receive a normal text message. It must persist, appear in the correct conversation, and preserve unread/read behavior.

### 5. Wake behavior
- crown wakes display;
- lift wakes display when enabled;
- sleeping touch remains disabled.

### 6. Home face
The v1.1 clock remains enlarged and optically centered; no new clipping or movement should appear.
