# M1.4.0 source audit

## Baseline

Immutable source baseline: ReticulumWatch M1.3.3.

## Intentionally changed source

- `platformio.ini` — dependency rebase and milestone macro.
- `src/config/BuildConfig.h` — version.
- `src/config/RnsBuildConfig.h` — explicitly keep RNS FS/provisioning features out of this migration.
- `src/reticulum/RnsCompat.h` — modern umbrella include.
- `src/reticulum/RnsNoopFileSystem.h` — microStore no-op filesystem adapter.
- `src/reticulum/ReticulumService.{h,cpp}` — modern filesystem integration + fail-closed signature self-test.
- `src/reticulum/WatchLoRaInterface.{h,cpp}` — exact modern bool `send_outgoing` adapter contract.
- `src/storage/StorageService.{h,cpp}` — explicit trust state using reserved LMX3 metadata bytes; backward-safe downgrade.
- `src/lxmf/LxmfService.cpp` — VERIFIED/FAILED determination from the corrected validation runtime.
- `src/ui/WatchUI.cpp` — explicit trust state presentation/version text.
- `src/main.cpp` — version/status text.

## Frozen behavior

The following must remain byte-identical to M1.3.3:

- `src/radio/RadioService.cpp`
- `src/radio/RadioService.h`
- `src/config/RadioConfig.h`
- both partition CSV files
- `docs/MASTER-BUILD-PLAN.md`

`WatchHardware` remains unchanged; the known weak button-haptic issue is deferred.

## Security invariants

- A stale vulnerable `Identity::validate()` implementation must fail the boot self-test because tampered signatures/messages would be accepted.
- The application must never convert a pre-M1.4 incoming history flag into `VERIFIED`.
- `VERIFIED` on a new incoming record requires both a recalled source identity and a successful current-runtime signature validation.
- `FAILED` requires a recalled source identity and an explicit validation failure.
- `UNKNOWN` does not imply failure; it means the identity needed to validate was not available.
- Outbound `SUBMITTED` continues to mean local Reticulum submission, not remote delivery.

## API migration checks

- application include boundary is `<microReticulum.h>`;
- `WatchLoRaInterface::send_outgoing(const RNS::Bytes&)` returns `bool`;
- microStore NoopFileSystem is used for the runtime filesystem contract;
- no legacy RatSpeak dependency remains in active `platformio.ini`;
- optional RNS filesystem persistence/provisioning is not enabled as a side effect of the rebase.

## Verification limitation

The assistant environment has no PlatformIO installation. This source audit cannot replace the actual ESP32-S3 PlatformIO build, flash and runtime regression on the user's watch.
