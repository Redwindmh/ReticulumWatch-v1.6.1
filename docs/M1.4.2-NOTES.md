# M1.4.2 — restore required microStore lifecycle filesystem

## Why this patch exists

M1.4.1 compiled, but runtime logs showed:

```text
[rns] ERROR: Reticulum start failed: FileSystem has not been registered
```

The physical SX1262 path remained alive and continued receiving Reticulum frames, but `ReticulumService::ready_` never became true. Because the service loop intentionally refuses to drain radio packets until Reticulum is ready, the first completed packet occupied the single handoff slot and later packets were dropped as `completed-packet slot busy`.

## Root cause

M1.4.1 incorrectly equated `RNS_USE_FS` being disabled with microReticulum not requiring a filesystem object. In microReticulum 0.5.0, those are separate concerns: persistence can be disabled while the OS abstraction still requires a registered `microStore::FileSystem` before `Reticulum::start()`.

M1.4.0 had the right lifecycle idea but used the wrong namespace for the resolved `microStore @ 0.1.7` adapter. The actual compiler error proved that the header and `microStore::FileSystem` existed, while `microStore::Adapters` did not. M1.4.2 therefore uses the 0.1.7 root-namespace adapter type `microStore::NoopFileSystem` and explicitly pins `attermann/microStore @ 0.1.7`.

## Changes

- restore a process-lifetime no-op `microStore::FileSystem`;
- initialize it and fail closed if `init()` fails;
- register it with `RNS::Utilities::OS` before `Reticulum::start()`;
- keep `RNS_USE_FS` and provisioning disabled, so ReticulumWatch's application identity/history still remain on the dedicated FFat partition;
- explicitly pin `attermann/microStore @ 0.1.7` in `platformio.ini`;
- make top-level boot reporting truthful: Reticulum/LXMF failure now prints `DEGRADED` instead of an unconditional success line;
- add `scripts/release_preflight.py` and `docs/RELEASE-CHECKLIST.md` so prior regression classes are checked before future packaging.

## Intentionally unchanged

The M1.4.1 radio service, SX1262 profile, RNode framing/split handling, microReticulum 0.5.0 interface adapter, storage/trust-state implementation, partitions, keyboard, and UI layout are unchanged except for active version strings.

## Expected startup sequence

```text
[rns] microStore 0.1.7 NoopFileSystem init returned true
[rns] registered required microStore no-op filesystem with RNS::Utilities::OS
[rns] Reticulum started as endpoint (transport disabled; probes enabled)
[security] Identity::validate self-test: valid=PASS tampered-signature=REJECT tampered-message=REJECT => PASS
...
[boot] M1.4.2 initialization complete; security gate + independent outbound LXMF ready
```

Any failure before LXMF readiness must instead end with a `DEGRADED` boot line.

## Verification status at packaging

The assistant environment does not contain PlatformIO, so this artifact is not claimed as PlatformIO build-verified. The mandatory local release preflight, partition validation, frozen-file hash audit, source-diff audit, C++ compatibility smoke test, and ZIP integrity checks are run before packaging.
