# M1.3.2 source/API audit

## LVGL 9.4.0 event choices

ReticulumWatch uses:

- `LV_EVENT_CLICKED` for ordinary `lv_button` controls;
- `LV_EVENT_VALUE_CHANGED` for the `lv_keyboard`/button-matrix.

The exact LVGL 9.4 documentation/source states that keyboard `LV_EVENT_VALUE_CHANGED` is emitted for a real key press/release (and repeat), with a valid button ID. This is deliberately narrower than listening for generic pointer/screen touches.

## LVGL 9.4.0 cursor compatibility

The textarea exposes `LV_PART_CURSOR`, whose documented line-caret styling uses a left border. The default LVGL theme itself styles this part with border colour/width/side and animation duration.

The exact v9.4.0 `lv_keyboard_set_textarea()` tag source does not reliably apply `LV_STATE_FOCUSED` to the target textarea. M1.3.2 therefore applies focus explicitly after attaching the keyboard and styles the caret locally.

## Haptic ownership

The proven LilyGo T-Watch S3 HAL already uses:

```cpp
instance.setHapticEffects(...);
instance.vibrator();
```

M1.3.2 adds `WatchHardware::tapHaptic()` using the same proven driver path. `WatchUI` never calls LilyGo/DRV2605 APIs directly.
