# M1.1 notes — Reticulum/LXMF interoperability rebase

## Why this milestone exists

M1.0/M1.0.1 proved that the T-Watch S3 could create a persistent Reticulum
identity, construct a valid `lxmf.delivery` announce, transmit it over the
SX1262, and be discovered by a normal Python Reticulum node. They did not prove
that normal addressed Reticulum/LXMF traffic could be received reliably.

Testing with both a custom Python sender and NomadNet showed that extending the
minimal M1.0.1 LXMF implementation was the wrong direction. M1.1 therefore
rebases protocol behavior on the working RatSpeak rsCardputer design instead of
adding another diagnostic-only patch.

## Reference implementation decisions

M1.1 follows the relevant rsCardputer standalone endpoint behavior:

1. Register a real microReticulum filesystem.
2. Register a full-duplex Reticulum interface around the physical LoRa device.
3. Run Reticulum as an endpoint with transport disabled and probe support enabled.
4. Create exactly one incoming `SINGLE` destination named `lxmf.delivery`.
5. Configure `PROVE_ALL` and accept incoming Links.
6. For opportunistic delivery, reconstruct the full LXMF wire form by prepending
   `packet.destination_hash()` before decoding.
7. For Link packet delivery, decode the packet payload directly because the full
   LXMF wire form is already present.
8. Decode through `LXMFMessage::unpackFull()` from the RatSpeak microReticulum fork.

## Pinned microReticulum

`platformio.ini` pins:

```text
https://github.com/ratspeak/microReticulum.git#290a1336ebe05782c80a1debf8a8da0316a88ae7
```

This commit is paired with the rsCardputer v1.7.9 interoperability work. It also
disables bz2 compression for MCU builds. For that reason M1.1's LXMF announce
uses an empty `supported_functionality` array. This prevents Python LXMF clients
from automatically compressing messages for a target that cannot decompress them.

## SX1262 receive lifecycle correction

M1.0.1 read completed packets with RadioLib but did not explicitly make returning
to continuous receive mode a guaranteed part of the post-read path.

M1.1 always re-arms `startReceive()` after:

- a valid received packet,
- a CRC/read error,
- an invalid/runt physical frame,
- and every transmission.

This is intentionally modeled after working embedded SX1262 Reticulum interfaces,
which explicitly return the radio to RX after processing.

## On-air framing

M1.1 retains RNode-compatible framing:

- physical packet byte 0: upper nibble random sequence, bit 0 split flag
- unsplit Reticulum payload: up to 254 bytes
- split Reticulum payload: two physical frames with the same sequence/flag
- Reticulum MTU: 500 bytes

The earlier hypothesis that this byte was only host-to-RNode serial framing was
incorrect; RatSpeak's standalone SX1262 implementation uses the same on-air
framing convention.

## LXMF announce data

M1.1 announces MessagePack equivalent to:

```text
[b"Reticulum Watch", nil, []]
```

The empty final array is deliberate: compression support is not advertised.

## Acceptance ladder

Do not expand the feature set until these pass in order:

1. Watch announce is validated and learned by Python Reticulum over the RNode.
2. A short addressed SINGLE packet reaches the watch and the watch emits its proof.
3. A short opportunistic LXMF message reaches `LXMFMessage::unpackFull()`.
4. A short direct Link LXMF message reaches `LXMFMessage::unpackFull()`.
5. The decoded message persists and appears on the watch UI.
6. Repeat after reboot with the same destination hash.

Large Resource-based LXMF, outbound user messaging, and transport-node behavior
are later milestones.
