# Reticulum Watch M0.2 — Storage + SX1262 substrate

M0.2 proves the two hardware resources the Reticulum stack will depend on before
microReticulum is linked into the firmware.

## Goals

- Mount the dedicated `reticulum` FAT partition at `/reticulum`.
- Format it automatically only if the fresh partition cannot be mounted.
- Create `/app` and `/rns` directories.
- Persist a boot counter to verify write/read survival across resets.
- Explicitly power and initialize the SX1262 through the Reticulum Watch radio layer.
- Return the radio to standby immediately; M0.2 never starts RX and never transmits.
- Keep the proven M0.1 display, touch, RTC, accelerometer, PMU and haptic baseline.

## Expected serial markers

On a fresh first boot, FAT formatting may add several seconds. Successful output includes:

```text
[storage] mounted /reticulum (label=reticulum)
[storage] total=... free=... boot_count=1
[storage] /app and /rns ready
[radio] SX1262 initialized successfully and returned to standby
[radio] M0.2 performs NO RF transmission
[boot] M0.2 initialization complete
```

Reset once without reflashing. The next boot should report `boot_count=2`. That is the
acceptance test for persistent storage.

## Why microReticulum moved to M0.3

The original roadmap grouped filesystem, radio and Reticulum together. Hardware testing
showed that isolating integration boundaries catches problems much faster. M0.3 will add
microReticulum only after storage persistence and SX1262 ownership are both confirmed on
the physical watch.
